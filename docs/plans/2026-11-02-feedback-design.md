# Artifact feedback design

Approved experience: a floating action button with draft-count badge expands a desktop panel/mobile bottom sheet. Select text or draw a region over any artifact; add/edit/delete draft comments. Send feedback delivers one batch for discussion to the originating communication channel and thread. No automatic revision. No permanent header/card/footer. Feedback never extends the one-hour public deadline.

## Trust boundaries
The claimed page becomes a trusted host with an opaque-origin sandboxed iframe containing either sanitized Markdown (including bundled Mermaid) or authored HTML/JS. Only the host owns feedback credentials, composer, send button and network requests. A small child bridge sends untrusted text-selection/viewport facts via postMessage; the host checks exact frame source and bounded message shape. The child cannot add/send comments. Region selection is a trusted parent overlay and works even when authored content disables the bridge. Frame ancestors are limited to the same origin; top-level host remains unframeable.

Feedback POST requires the claimed browser session, exact Origin, JSON content type and a separate per-artifact double-submit CSRF token. Limits: 32 KiB body, 20 comments per batch, 1000 chars per comment, 2000 chars per quote, 10 batches/artifact. Each artifact is immutable, so its random artifact ID identifies the version. UUID batch IDs deduplicate retries; mismatched repeated content is rejected. No client-controlled route, model ID, filesystem path or channel destination is accepted.

At creation capture the SDK's opaque original-session target, trusted agent ID and original delivery context. On submission enqueue a host-admitted session event bound to that target, containing explicitly untrusted annotation JSON and fixed discussion-only instructions. Report queued separately from confirmed delivery. Ambiguous/failed outcomes must never trigger automatic duplicate sends. Plugin reload/restart drops the opaque handles: fail closed for feedback on old artifacts rather than recapture a potentially reset/retargeted conversation. Reading remains available until normal expiry; ask for a fresh artifact to restore feedback. Record this limitation prominently.

## Frontend/backend contract
Host DOM: iframe#artifact-content with sandbox=allow-scripts, div#artifact-feedback with data-path (artifact document path), data-artifact-id, data-csrf (43-char token), data-enabled (true/false). Assets feedback.js and feedback.css initialize the overlay. Inner iframe loads bridge.js as a classic deferred script.
Child->parent messages: {type:'clawtifact:selection',anchor:{type:'text',quote,prefix,suffix}} and {type:'clawtifact:viewport',scrollX,scrollY,viewportWidth,viewportHeight}. Parent->child: {type:'clawtifact:highlight',anchor} (optional feedback focus), {type:'clawtifact:clear'}. Never send csrf/session/feedback draft to child.
POST <data-path>/feedback body {id: UUID string,csrf,comments:[{text,anchor}]}. anchors: text shape above; general {type:'general'}; region {type:'region',x,y,width,height,scrollX,scrollY,viewportWidth,viewportHeight} with normalized region dimensions, finite bounded scroll and viewport sizes. Success 202 {batchId,status:'queued'|'delivered'|'failed'|'uncertain'}. GET same endpoint returns {enabled,batches:[{batchId,status}]}; claim/auth/expiry failures return uniform 404. Other failures: malformed=400, duplicate mismatch=409, limit=429, unavailable=503. Host UI must not say delivered for queued. Keep drafts until confirmed delivery; no auto-resubmission on refresh.

## Verification
Test failing HTTP auth/CSRF/idempotency/expiry cases before backend implementation. Test browser protocol/draft state and injection-resistant rendering. Run real browser interaction for both formats and malicious child forgery attempts without making a public tunnel. Run full build/tests/audit and an independent security review before any deployment or release. Preserve the prior release; implement in isolated feature worktree.
